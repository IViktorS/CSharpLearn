# 9.8 CI — задачи

Конспект — `9.8-CI.md` в этой папке. Workflow живёт в `.github/workflows/` **в корне репозитория**, не здесь.

**Push делаешь ты.** Это внешнее действие: оно публикует код на GitHub и запускает там прогоны. Результаты смотри на вкладке **Actions** репозитория и в значке рядом с коммитом на главной странице.

**Проверяющий здесь — GitHub, а не я.** Заранее прогнать Actions мне негде. Поэтому сначала пиши предсказание, потом пушь и сверяйся с настоящим прогоном. Результаты прогонов потом перенесём в конспект как `[проверено]`.

Ориентир по времени: около двух часов на всё, включая ожидание прогонов. Задачи 1 и 4 — главные; если время кончается, задачи 2 и 3 можно сделать вторым заходом.

## Задача 1: свой workflow

Создай файл `.github/workflows/build.yml`. Требования:

- запускается на **push в `master`** и на **pull request в `master`**;
- собирает **всё решение** `CSharpLearn.slnx`, а не один проект, в конфигурации `Release`;
- машина — такая, на которой соберётся и WPF-проект;
- .NET 10;
- после сборки выкладывает **артефакт** с собранным WPF-приложением — папка `CSharpLearn/bin/Release/net10.0-windows/` — под именем `csharplearn-wpf`. Если папка окажется пустой или её не будет — шаг должен **упасть**, а не промолчать.

Закоммить и запушь в `master`.

```
ПРЕДСКАЗАНИЕ (1) что увидишь рядом с коммитом на главной странице репозитория
                 и на вкладке Actions в первые секунды после push, а что — через пару минут:

ПРЕДСКАЗАНИЕ (2) сколько примерно займёт прогон — секунды, минуты, десятки минут?
                 Какой шаг будет самым долгим и почему:

ПРЕДСКАЗАНИЕ (3) скачай артефакт со страницы прогона, распакуй и запусти .exe.
                 Запустится ли на твоей машине? Почему:

ПРЕДСКАЗАНИЕ (4) в каком из предсказаний уверенность ниже всего? Номером:
```

## Задача 3: убедиться, что CI ловит ошибку

Зелёный статус ничего не стоит, пока ты не видел, как он краснеет (грабля 1 конспекта).

1. Создай ветку `ci-broken` от `master`.
2. Сломай компиляцию в `Basics` одной строкой — например, присвой строку переменной типа `int`.
3. Закоммить и запушь **ветку** `ci-broken`.

```
ПРЕДСКАЗАНИЕ (1) запустится ли твой workflow на этот push? Ответ ищи в своём же файле,
                 в секции on:

ПРЕДСКАЗАНИЕ (2) если не запустится — что нужно сделать, чтобы он проверил эту ветку,
                 не сливая её в master:
```

4. Сделай то, что предсказал в (2), и дождись прогона.

```
ПРЕДСКАЗАНИЕ (3) на каком шаге упадёт прогон, и как в логе найти строку с ошибкой:
```

5. Найди в логе ту самую ошибку компилятора и выпиши её сюда.
6. Закрой pull request без слияния и удали ветку.

## Задача 4 (тип 3, ревью): найди, где врёт этот workflow

Коллега прислал workflow для этого репозитория. Синтаксис правильный, GitHub его принимает, а вкладка Actions ни на что не жалуется. Коллега говорит: «CI настроен, всё зелёное».

```yaml
name: build

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v7

      - uses: actions/setup-dotnet@v6
        with:
          dotnet-version: '10.0.x'

      - name: Build
        run: dotnet build Basics/Basics.csproj -c Release
        continue-on-error: true

      - uses: actions/upload-artifact@v7
        with:
          name: csharplearn-wpf
          path: CSharpLearn/bin/Release/net10.0-windows/
```

Сколько в нём ошибок, не сообщаю. Пиши **до** того, как что-либо запускать, по каждой найденной:

```
ЗАМЕЧАНИЕ (n):
  что неверно —
  когда проявится (что должно случиться в репозитории, чтобы это стало видно) —
  почему —
  как поймать (какой эксперимент покажет, что проблема есть) —
```

И отдельно:

```
ЗАМЕЧАНИЕ (итог) одной фразой: насколько можно доверять словам «всё зелёное»
                 про этот workflow и почему:
```

Разбор пойдёт по найденному и пропущенному. Для пропущенного главный вопрос — каким экспериментом это можно было поймать.
