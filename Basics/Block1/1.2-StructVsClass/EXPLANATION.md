# 1.2 — struct vs class: когда что выбирать

## Природа
- **`class`** — про **идентичность**. Два объекта с одинаковыми полями — это два разных объекта.
- **`struct`** — про **значение**. Ведёт себя как число/координата: `(3,5)` и `(3,5)` — одно значение.

## Ключевые различия
| | `struct` | `class` |
|---|---|---|
| Категория | value type | reference type |
| Где живёт | inline (в стеке/внутри владельца) | в куче, переменная хранит ссылку |
| Присваивание | копия всех полей | копия ссылки |
| Наследование | ❌ (только реализация интерфейсов) | ✅ |
| Значение по умолчанию | не `null`, все поля обнулены | `null` |
| Равенство по умолчанию | по значению (полям) | по ссылке |

## Правило выбора
**По умолчанию — `class`.** Выбирай `struct`, только если ВСЁ сразу: тип маленький (≈≤16 байт), **неизменяемый (immutable)**, ведёт себя как единое значение, создаётся в больших количествах.
Считаем не число полей, а «это одно логическое значение или сущность с идентичностью?». `Money(Amount, Currency)` — это value object (один смысл), поэтому кандидат в `struct`/`record`.

## Грабли struct
- **Мутация копии** в коллекциях: `list[i].X = 5` для `List<struct>` — ошибка компиляции (CS1612), т.к. индексатор `List`/`Dictionary` возвращает **копию**. А `arr[i].X = 5` для массива работает — элемент массива это **переменная-ячейка**.
- **`default` без null**: у `struct` нет состояния «не создан», все поля обнулены.

## Равенство
- `struct`: `.Equals()` сравнивает по полям (медленно, через рефлексию → для частых сравнений `record struct`). Оператор `==` по умолчанию **не определён**.
- `class`: и `==`, и `.Equals()` по умолчанию сравнивают ссылки.

## Копия vs переменная при доступе к элементу
Переменную (мутация «останется») дают только: **элемент массива** и **`ref`-возвращающие члены** (`Span<T>`, `CollectionsMarshal`). Всё остальное (`List`, `Dictionary`, `foreach`, свойства) — **копия**.
