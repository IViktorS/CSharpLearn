# 1.11 — out / ref / in параметры

## Суть
По умолчанию аргумент передаётся **по значению** (копия значения / копия ссылки). `ref`/`out`/`in` передают **саму переменную по ссылке** (псевдоним, alias) — метод работает напрямую с переменной вызывающего кода.

## ref — двусторонняя передача
```csharp
void Increment(ref int x) => x++;
Increment(ref a);   // меняет саму a
```
- Псевдоним переменной; метод и читает, и меняет оригинал.
- Переменная **должна быть инициализирована ДО вызова**.
- `ref` пишется и в сигнатуре, и в вызове.

## out — только вернуть наружу
```csharp
bool TryDivide(int a, int b, out int result) { ... }
```
- Метод **обязан присвоить** `out` перед возвратом (проверяет компилятор).
- Инициализация до вызова **не нужна**; входное значение метод читать не может.
- Паттерн `TryXxx`: `bool` через `return` (удалось/нет) + значение через `out` (`int.TryParse`, `Dictionary.TryGetValue`, `Enum.TryParse`).
- Современно: `if (int.TryParse(s, out int n)) { ... }`.

## in — по ссылке только для чтения
- Псевдоним как `ref`, но метод **не может менять** параметр.
- Смысл: не копировать **большой `struct`** при передаче, гарантируя неизменность. Для мелких аргументов не нужен.

## Сводка
| | Направление | Инициализация до | Обязан присвоить | Может менять |
|---|---|---|---|---|
| (default) | внутрь (копия) | да | — | копию |
| `ref` | внутрь+наружу | **да** | нет | да |
| `out` | наружу | нет | **да** | да |
| `in` | внутрь (по ссылке) | да | нет | **нет** |

## Связь с 1.1
`ref string` позволяет **переприсвоить саму ссылку** снаружи: `TryAppend` без `ref` строку не менял, с `ref` — меняет.
