# 1.9 — readonly vs const

## const — константа времени компиляции
- Значение известно на **компиляции**, задаётся при объявлении литералом/константным выражением.
- **Неявно `static`** → обращение через тип (`MathStuff.Pi`).
- **Инлайнится**: компилятор подставляет само значение в место использования.
- Только примитивы/`string`/`enum`. `const DateTime.Now` нельзя — вычисляется в рантайме.

## readonly — поле только для чтения (runtime)
- Значение фиксируется в **рантайме**: при объявлении **или в конструкторе**.
- Обычное поле экземпляра (**своё у каждого объекта**), можно `static readonly`.
- Не инлайнится — настоящее обращение к полю.
- Любой тип, включая ссылочный.

## Сравнение
| | `const` | `readonly` |
|---|---|---|
| Когда задаётся | компиляция | рантайм (объявление/конструктор) |
| static? | всегда | нет (можно static readonly) |
| Типы | примитивы/string/enum | любые |
| В коде | инлайнится | обращение к полю |

## Грабля const — версионирование между сборками
Из-за инлайна значение `const` **впечатывается** в потребителя при его компиляции. Изменил `const` в библиотеке A и пересобрал только A — потребитель B видит **старое** значение, пока сам не пересоберётся. У `static readonly` такого нет (значение читается в рантайме).
**Вывод:** публичные значения, которые могут меняться между версиями → `static readonly`; `const` — для вечных величин (π).

## readonly и ссылочные типы
`readonly` защищает **ссылку**, не содержимое:
```csharp
readonly List<int> Items = new();
Items.Add(5);          // ✅ содержимое менять можно
Items = new List<int>(); // ❌ переприсвоить ссылку нельзя (CS0191)
```

## Выбор
Известно на компиляции и вечно → `const`. Известно только в рантайме / разное у объектов (Id, конфиг) → `readonly`.
