# 1.10 — static (класс / метод / поле / конструктор)

## Общая идея
`static` = принадлежит **типу**, а не экземпляру. Существует в единственном экземпляре на весь тип, доступно без создания объекта.

## Статическое поле
Одно на весь тип, общее для всех объектов. Обращение через тип (`Counter.Total`). Живёт до конца приложения → это **глобальное состояние**.

## Статический метод
Не привязан к экземпляру, **нет `this`** → не может обращаться к нестатическим членам напрямую (только к статике/параметрам). Экземплярный метод к статике обращаться может.

## Статический класс
Только статические члены; **нельзя `new`** и нельзя наследовать. Контейнер утилит (`Math`, `Console`, `File`). Наши `TopicRegistry`, `Enums` и т.д. — статические классы.

## Статический конструктор
```csharp
static Config() { ... }   // без модификатора доступа, без параметров
```
- Вызывается **автоматически, один раз, лениво** — перед первым обращением к типу (первый `new` ИЛИ первое обращение к любому static-члену).
- Вручную вызвать нельзя.
- Нужен для **логики** инициализации static-полей.

## Где живёт в памяти
- static-поле (значимый тип) — в хранилище статики типа (loader heap), живёт пока загружен тип.
- static-поле (ссылочный тип) — ссылка в статике типа (это **GC-корень**), объект в куче → **не собирается GC**, пока жив тип → отсюда «утечки».
- статический класс/метод — метаданные (MethodTable) + код в области загрузчика, один раз.

## Грабли
- **Глобальное изменяемое состояние** → гонки, трудно отследить. Держи статику **неизменяемой** (`static readonly`).
- Из static-метода не достучаться до `this`-полей.
- Долгое время жизни → большой объект в static = «утечка» на всё приложение.
