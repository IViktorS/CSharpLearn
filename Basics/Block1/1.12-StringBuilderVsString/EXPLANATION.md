# 1.12 — StringBuilder vs string

## Корень проблемы
`string` **иммутабельна**. Любое «изменение» создаёт **новую** строку:
```csharp
s = s + "!";   // новая строка, старая → мусор
```

## Почему конкатенация в цикле дорогая
```csharp
string result = "";
for (int i = 0; i < N; i++) result += i;   // каждый раз НОВАЯ строка
```
На каждой итерации: новый объект в куче + копирование всего предыдущего содержимого + старая строка в мусор. Объём копирования растёт ~O(N²), плюс нагрузка на GC.

## StringBuilder — изменяемый буфер
```csharp
var sb = new StringBuilder();
for (int i = 0; i < N; i++) sb.Append(i);
string result = sb.ToString();   // ОДИН раз материализуем
```
- Держит расширяемый буфер (массив char), дописывает **на месте**, без новых строк.
- Буфер растёт удвоением ёмкости → перевыделений мало (логарифмически).
- Методы: `Append`, `AppendLine`, `Insert`, `Remove`, `Replace`, `Clear`, `Length`. `ToString()` — финальная строка.

Аналогия: `string +=` в цикле : `StringBuilder` = `ArrayList` : `List<int>` (много мусора vs один растущий буфер).

## Когда что
| Ситуация | Что |
|---|---|
| Пара склеиваний, фиксированное число | `string` / интерполяция `$"..."` |
| Склеивание в **цикле** / неизвестное число | **`StringBuilder`** |
| Соединить готовую коллекцию | `string.Join(sep, values)` |

**Не** тащить `StringBuilder` всюду — для `$"{name}: {age}"` обычный `string` читаемее и не медленнее.

## string.Join
`string.Join(sep, values)` вставляет разделитель **только между** элементами (нет ведущего) и обрабатывает **всю коллекцию за один вызов** — цикл не нужен.

## Эксперимент
30000 итераций: `string +=` → **95 сборок Gen0**; `StringBuilder` → **0**.

## Иммутабельность
`ToUpper()`, `Substring()`, `Replace()` возвращают **новую** строку, оригинал не меняется.
