# 1.20 Рефлексия: чтение метаданных, цена, когда не надо

Вторая половина механизма из 1.19: там пометку ставили, здесь её читают — и не только её.

Задачи — `ReflectionBasics.cs`, запуск `dotnet run --project Basics -- 1.20`.

Пометки происхождения: **[проверено]** — собрано и запущено, вывод приложен; **[измерено]** — есть числа замера; **[док]** — ссылка на документацию; без пометки — утверждение Claude.

> Мини-справка: **`nameof(X.Member)`** — компилятор подставляет имя члена строкой (`"Member"`), но сперва проверяет, что такой член есть. Опечатка — ошибка сборки.

> Мини-справка: **`InnerException`** — у исключения может быть «вложенное»: настоящая причина, обёрнутая в другое исключение. Подробно — тема 10.2.

## 1. Зачем / какую проблему решает

Обычный код знает типы **при компиляции**: пишешь `p.Age` — компилятор проверяет, что у типа есть `Age`. Но бывает код, который работает с типами, о которых при компиляции **ничего не знает**:

- сериализатор превращает в JSON **любой** объект (11.2);
- тестовый фреймворк находит **все** методы с `[Fact]` (9.1);
- биндинг `{Binding Name}` из 7.3 ищет свойство **по строке** — поэтому опечатка `Nmae` и скомпилировалась: компилятор этой строки не проверяет, имя ищется при выполнении.

Рефлексия — способ во время выполнения **спросить у типа, что в нём есть**, и работать с найденным: читать, писать, вызывать, создавать.

Ты ею уже пользовался в харнессах, не называя: `GetCustomAttribute` в 1.19, `GetGenericTypeDefinition` в 1.17, `GetField(...).FieldType` при разборе `T?` в 1.18.

> [док] [Reflection in .NET](https://learn.microsoft.com/dotnet/fundamentals/reflection/overview)

## 2. Как устроено

### Метаданные и объект `Type`

Компилятор кладёт в сборку не только код, но и **описание**: какие типы, какие у них поля, свойства, методы, атрибуты, модификаторы. Рефлексия это описание читает.

Входная точка — объект `Type`, описание одного типа. Получить его можно двумя способами, и они отвечают на **разные вопросы**:

| | Что возвращает | Когда известно |
|---|---|---|
| `typeof(X)` | тип `X`, как написан в коде | при компиляции |
| `obj.GetType()` | **фактический** тип объекта | при выполнении |

**[проверено]**:

```
object o = "abc":   typeof(object) = Object,  o.GetType() = String
object boxed = 5:   boxed.GetType() = Int32
```

Та же развилка, что в 1.16 и 1.12: **объявленный тип переменной** против **фактического типа объекта**. `typeof` спрашивает код, `GetType()` спрашивает объект. Коробка из 1.4 знает свой тип — поэтому `boxed.GetType()` даёт `Int32`, а не `Object`.

### От `Type` — к членам

У `Type` есть методы, возвращающие описания членов: `GetFields()`, `GetProperties()`, `GetMethods()`, `GetField("имя")` и так далее. Каждое описание — объект (`FieldInfo`, `PropertyInfo`, `MethodInfo`), через который член можно прочитать, записать или вызвать.

Все примеры этого раздела и граблей 1–2 получены на одном классе. Он показан целиком, чтобы было видно, откуда берутся имена:

```csharp
public class Secret
{
    public int Open = 1;                      // открытое поле
    private int _hidden = 2;                  // закрытое поле
    public readonly int Ro = 3;               // поле только для чтения
    public const int Const = 4;               // константа
    public static readonly int StaticRo = 5;  // статическое поле только для чтения
    public int Prop { get; set; } = 6;        // авто-свойство
    public int GetOnly { get; } = 7;          // авто-свойство без сеттера
    public int Hidden => _hidden;             // вычисляемое — чтобы видеть _hidden снаружи
}
```

**[проверено]**, что рефлексия видит у `Secret`:

```
GetFields()                       : Open, Ro, StaticRo, Const
GetFields(NonPublic | Instance)   : _hidden, <Prop>k__BackingField, <GetOnly>k__BackingField
GetProperties()                   : Prop, GetOnly, Hidden
```

По умолчанию видно только открытое. Флаг `BindingFlags.NonPublic` открывает закрытое — **включая скрытые поля авто-свойств из 1.6**. Это и есть то «скрытое backing-поле», про которое говорилось там: у него есть настоящее имя, `<Prop>k__BackingField`, и рефлексия его видит.

### `new T()` — это рефлексия

**[проверено]**, что компилятор вставил в тело `static T Make<T>() where T : new() => new T();`:

```
call Activator.CreateInstance
```

Не прямой вызов конструктора, а `Activator.CreateInstance<T>()` — создание объекта по типу. Ограничение `new()` из 1.18 нужно ровно затем, чтобы **при компиляции** гарантировать: конструктор без параметров есть. Без этой гарантии та же операция падает при выполнении — **[проверено]**: `Activator.CreateInstance` для типа без такого конструктора бросает `MissingMethodException`.

## 3. Синтаксис

Примеры раздела — на классе `Worker`; на нём же сделан замер цены в грабле 4:

```csharp
public class Worker
{
    public int Age { get; set; } = 30;
    public int AddYears(int y) => Age + y;
}
```

```csharp
var worker = new Worker();                     // Age = 30

Type t = typeof(Worker);                       // Worker            (или worker.GetType())

PropertyInfo prop = t.GetProperty(nameof(Worker.Age));
                                               // Int32 Age         — описание свойства, не его значение
object value = prop.GetValue(worker);          // 30                — упакованный int: value.GetType() = Int32
prop.SetValue(worker, 42);                     // теперь worker.Age = 42

MethodInfo m = t.GetMethod(nameof(Worker.AddYears));
                                               // Int32 AddYears(Int32)
object result = m.Invoke(worker, new object[] { 1 });
                                               // 43                — 42 + 1, тоже упакованный int

object made = Activator.CreateInstance(t);     // новый Worker, Age = 30 — НЕ тот же объект, что worker

var attr = prop.GetCustomAttribute<UnitAttribute>();
                                               // null              — у Age нет пометки [Unit]
```

**[проверено]**: комментарии справа сняты с прогона именно этого кода.

`UnitAttribute` — атрибут из задач 1.19:

```csharp
public class UnitAttribute : Attribute
{
    public string Symbol { get; }
    public UnitAttribute(string symbol) => Symbol = symbol;
}
```

`attr` вышел `null`, потому что `Age` ничем не помечен, — то же поведение, что у непомеченного свойства в 1.19. Будь свойство объявлено как `[Unit("лет")] public int Age { get; set; }`, вернулся бы объект атрибута.

Закрытые члены: `t.GetField("_hidden", BindingFlags.NonPublic | BindingFlags.Instance)`. Флаги складываются через `|` — это `[Flags]`-перечисление из 1.7.

## 4. Грабли

**1. Модификаторы доступа и `readonly` — проверки компилятора, а не стена в рантайме.**

**[проверено]**:

| Что | `SetValue` | Результат |
|---|---|---|
| `private int _hidden` | ок | значение изменилось |
| `public readonly int Ro` | **ок** | **значение изменилось** |
| `static readonly int StaticRo` | `FieldAccessException` | не изменилось |
| `const int Const` | `FieldAccessException` | (`IsLiteral = True`) |
| get-only свойство `GetOnly { get; }` | `ArgumentException` — сеттера нет | — |
| его скрытое поле `<GetOnly>k__BackingField` | **ок** | **значение изменилось** |

`private` (1.8) и `readonly` (1.9) — обещания, которые проверяет **компилятор**: он не даст написать такой код. Рефлексия идёт в обход компилятора, и для полей экземпляра эти обещания не действуют. Исключений два, и оба объяснимы: `const` — вообще не поле с памятью, а литерал, подставленный в места использования (1.9); `static readonly` рантайм защищает отдельно.

Вывод не «рефлексией можно всё», а другой: **такие обещания держатся на том, что все играют по правилам компилятора.** Код, который пишет в чужие `private` и `readonly` поля, ломает чужие инварианты и ломается сам при первом переименовании.

**2. Имена — строки, опечатка всплывает только при выполнении.**

**[проверено]**: `GetProperty("Porp")` — опечатка в `Prop` класса `Secret` — возвращает `null` — без исключения. Падение случится строкой позже, на `null.GetValue(...)`, далеко от места ошибки. Та же природа, что у тихого биндинга в 7.3.

Лечится `nameof`: `GetProperty(nameof(Secret.Prop))` — опечатка становится ошибкой сборки.

**3. Всё через `object` — значит, упаковка. Откуда именно берутся байты.**

Посмотри на сигнатуры двух главных методов:

```csharp
object GetValue(object obj)                       // результат — object
object Invoke(object obj, object[] parameters)    // аргументы — массив object, результат — object
```

Рефлексия не знает типов заранее, поэтому всё, что через неё проходит, проходит **как `object`**. А значение значимого типа (`int`, `double`), чтобы стать `object`, упаковывается — это 1.4. Значение ссылочного типа (`string`) — уже ссылка, ему упаковка не нужна.

**Строительные блоки** — **[измерено]**, байт на одно действие:

| Что создаётся | Байт | Откуда размер |
|---|---|---|
| коробка для `int` | 24 | заголовок объекта 16 + место под значение, округлённое до 8 |
| коробка для `double` | 24 | то же: `double` занимает 8, округлять не нужно |
| `string` → `object` | **0** | это уже ссылка, коробка не создаётся |
| массив `object[N]` | 24 + 8·N | заголовок 16 + длина массива 8 + по 8 байт на каждую ссылку |

Для массивов замерено по точкам: `object[0]` — 24, `object[1]` — 32, `object[2]` — 40, `object[3]` — 48. Ссылка на 64-битной машине занимает 8 байт (`IntPtr.Size` = 8 **[проверено]**). Сами цифры размеров — замер; расшифровка «заголовок 16 + …» — утверждение Claude, она объясняет числа, но отдельно не проверялась.

**Ячейка массива — это ссылка, а не объект.** В `object[]` каждый элемент — ссылка, 8 байт. Объект, на который она указывает, лежит в куче отдельно и считается отдельно:

```
new object[] { 1, "привет" }                        — 64 байта всего

массив object[2] — 40 байт
┌─────────────────┬──────────┬──────────┬──────────┐
│ заголовок   16  │ длина  8 │ ссылка 8 │ ссылка 8 │
└─────────────────┴──────────┴────┬─────┴────┬─────┘
                                  │          └──→ "привет"  — литерал, уже существует (1.12): +0
                                  └──→ [коробка: 1]  — новая, создана ради этой ячейки:   +24
```

*(Схема на уровне «какие объекты в куче и сколько они весят»; внутреннее устройство заголовка не показано.)*

**[измерено]**:

| Массив | Байт | Из чего |
|---|---|---|
| `new object[3]`, все ячейки `null` | 48 | только массив — размер зависит от длины, не от содержимого |
| `new object[] { 1 }` | 56 | массив 32 + коробка 24 |
| `new object[] { "привет" }` | 32 | только массив: строка уже существует |
| `new object[] { 1, "привет" }` | 64 | массив 40 + коробка 24 |
| `new int[] { 1 }` | 32 | только массив: в `int[]` число лежит прямо в ячейке, коробки нет |

Последняя строка — то же различие, что в 1.17 между `ArrayList` (32 байта на элемент: ячейка-ссылка 8 + коробка 24) и `List<int>` (4 байта: число прямо в ячейке).

**Разбор по шагам — что создаётся в каждой строке.**

Чтение свойства `int Age`:

```csharp
object v = prop.GetValue(p);
//         └─ свойство вернуло int; чтобы отдать его как object, рантайм кладёт его в коробку → 24
//
// итого 24 байта
```

Вызов метода `int AddYears(int)`:

```csharp
object r = meth.Invoke(p, new object[] { 1 });
//                        │              └─ 1 — это int; чтобы лечь в ячейку object[], он упаковывается → 24
//                        └─ массив для аргументов создаёшь ТЫ, прямо в этой строке: object[1] → 32
// метод вернул int; Invoke отдаёт его как object → ещё одна коробка → 24
//
// итого 32 + 24 + 24 = 80 байт
```

Отдельная проверка того, что массив и коробка для аргумента рождаются в одной записи: `new object[] { 1 }` сама по себе даёт **56 байт** — ровно 32 + 24 **[измерено]**.

**Правило подсчёта:** пройди по всем значениям, которые пересекают границу «обычный код ↔ `object`» в обе стороны — аргументы на входе, результат на выходе. Каждое значение значимого типа даёт коробку, каждое ссылочное — ноль. К этому прибавь массив аргументов, если он создаётся.

**4. Цена во времени.**

**[измерено]**, 10 000 000 вызовов, Release, класс `Worker` из раздела 3 (в харнессе он назывался `Person`, члены те же):

| Как | нс/вызов | байт/вызов |
|---|---|---|
| прямое чтение `p.Age` | 0,31 | 0 |
| `prop.GetValue(p)`, `PropertyInfo` закэширован | 12,75 | 24 |
| `GetProperty("Age").GetValue(p)` каждый раз | 28,74 | 24 |
| прямой вызов `p.AddYears(1)` | 0,33 | 0 |
| `meth.Invoke(p, new object[] { 1 })` | 23,00 | 80 |

Байты в последнем столбце — те самые 24 и 80 из разбора выше. По времени:

- рефлексия дороже прямого доступа **на один-два порядка**. Точное отношение не важно: прямой доступ JIT почти растворил в цикле, поэтому «в сорок раз» — оценка снизу;
- поиск члена по имени при каждом вызове — ещё **вдвое** дороже, поэтому `PropertyInfo` стоит найти один раз и сохранить;
- `Invoke` дороже `GetValue`: больше коробок, плюс перед вызовом рантайм сверяет число и типы аргументов в массиве и распаковывает их. Последнее — утверждение Claude; замер показывает только итоговую разницу.

**5. Исключение изнутри вызванного метода приходит обёрнутым.**

```csharp
public class Thrower
{
    public void Boom() => throw new InvalidOperationException("внутри метода");
}

try
{
    typeof(Thrower).GetMethod("Boom")!.Invoke(new Thrower(), null);
}
catch (Exception ex)
{
    // ex                — TargetInvocationException
    // ex.InnerException — InvalidOperationException «внутри метода»
}
```

**[проверено]**: метод бросает `InvalidOperationException`, а снаружи `Invoke` ловится `TargetInvocationException`; настоящее исключение — в его `InnerException`. Кто ловит `catch (InvalidOperationException)` вокруг `Invoke`, ничего не поймает.

**6. `GetType()` у `int?`.**

**[проверено]**:

```
int? n = 5:     n.GetType()  = Int32         (а typeof(int?) = Nullable`1)
int? z = null:  z.GetType()  -> NullReferenceException
```

`GetType()` объявлен у `object`, поэтому `Nullable` перед вызовом упаковывается — а `Nullable` при упаковке **не создаёт коробку `Nullable`**: со значением он упаковывается как сам `int`, без значения превращается в `null`. **[проверено]**: `object bn = (int?)5` даёт `bn.GetType() = System.Int32` и `bn is int = True`; `object bz = (int?)null` даёт `bz == null = True`. Отсюда и `Int32`, и падение. Связь с 1.5 и 1.18: `int?` — особый тип, и рантайм обходится с ним особо.

## 5. Когда что

| Ситуация | Что брать |
|---|---|
| тип известен при компиляции | **не рефлексию** — обычный доступ, дженерик (1.17) или ограничение (1.18) |
| нужно `new T()` | ограничение `where T : new()` — та же рефлексия, но с проверкой при компиляции |
| код работает с **любым** типом: сериализация, логирование «всех свойств», загрузка плагинов | рефлексия |
| прочитать атрибуты | рефлексия — других способов нет (1.19) |
| диагностика и харнессы — заглянуть внутрь `List<T>`, узнать фактический тип | рефлексия; это её законная и самая частая у нас роль |
| много вызовов в горячем цикле | рефлексию — один раз на поиск, результат сохранить; если и этого мало — генераторы кода (7.11) |

Правило: **рефлексия нужна там, где тип неизвестен при компиляции.** Если известен — она только отнимает проверки компилятора и добавляет цену.

## 5б. Где встретится в реальном коде

- **`TargetInvocationException` в логах** с осмысленным `InnerException` — почти наверняка что-то вызвано через рефлексию: фреймворк, плагин, обработчик по имени. Читать надо внутреннее исключение, внешнее — обёртка.
- **`MissingMethodException` при старте** в коде с `Activator.CreateInstance` или в DI-контейнере — у создаваемого типа нет нужного конструктора. Признак: компилятор молчал, упало при выполнении.
- **Методы вида `ToDictionary(object)` / `Dump(object)` / «скопировать все свойства»** через `GetProperties()` — классика логирования и маппинга. Смотреть, кэшируются ли `PropertyInfo` — если поиск идёт на каждый вызов, это заметная цена в горячем пути.
- **`BindingFlags.NonPublic` в тестах** — тест лезет в закрытое поле, чтобы проверить состояние. Работает, но ломается при переименовании поля; на ревью это обычно повод спросить, почему состояние не видно снаружи.
- **«После переименования свойства перестало работать, а сборка зелёная»** — где-то имя записано строкой: рефлексия, биндинг, сериализация по имени. Лечится `nameof` там, где он применим.

## 6. Опирается на

Названо пользователем на шаге 6, механизмы уточнены при разборе.

| Тема | Что именно здесь работает |
|---|---|
| **1.1** | Упаковываются только значимые типы; ссылочный уже ссылка — поэтому `GetValue` у `string` стоит 0 байт, а у `int` и `double` по 24 |
| **1.4** | Рефлексия пропускает всё через `object`: каждое значимое значение на входе и выходе — коробка. Коробка появляется при любом переходе «значимый → ссылочный», не только к `object` |
| **1.5** | `int?` при упаковке превращается в `int` или в `null` — отсюда `n.GetType()` = `Int32` и `NullReferenceException` у пустого |
| **1.6** | Свойство — это методы доступа плюс скрытое поле. Get-only — метода записи нет; `init` и `private set` — метод записи есть, поэтому `SetValue` проходит |
| **1.9** | `const` — литерал без памяти, подставленный при компиляции: записать некуда, `FieldAccessException`. `readonly` у поля экземпляра — проверка компилятора |
| **1.12** | `string.Join` в `Dump` (использование, а не механизм) |
| **1.8** | *Назван на вопросе (б) — через промахи (3) и (4) задачи 1.* `private` — обещание, которое проверяет компилятор; рефлексия идёт в обход него |
| **1.7** | *Назван на вопросе (б) — через собственный вопрос «почему `\|`, а не `\|\|`».* `BindingFlags` — `[Flags]`-перечисление: `\|` складывает биты, метод проверяет каждый бит отдельно |

Не названы, дописаны при разборе:

- **1.10** — `Static` против `Instance` в `BindingFlags`; статическое `Instances` попало в `Dump`, хотя это состояние типа, а не объекта.
- **1.16, 1.17** — `typeof` против `GetType()`: объявленный тип против фактического. В обобщённом `Dump<T>` запись `typeof(T)` для переменной типа `object` дала `Object { }`.
- **1.18** — `new T()` компилируется в `Activator.CreateInstance<T>()`; ограничение `new()` переносит проверку «конструктор есть» с выполнения на компиляцию.

## 7. Будет позже

- **Быстрый доступ без рефлексии на каждом вызове** — делегаты (Блок 3): найти член один раз, получить делегат и дальше вызывать почти как напрямую.
- **Генераторы кода** (7.11): то, что раньше делалось рефлексией при выполнении, пишется при компиляции — без цены и с проверкой.
- **Рефлексия и наследование** — `GetType()` на наследнике, `BindingFlags.DeclaredOnly` (Блок 2).
- **Обрезка сборок и AOT** — почему рефлексия по строковым именам мешает выкидывать неиспользуемый код. Анонс, отдельной темы нет.
