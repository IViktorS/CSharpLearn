# 1.5 — null, Nullable<T>, ?., ??, ??=, NRT

## null
«Ссылка ни на что». Есть только у **ссылочных** типов. Обращение к члену по `null` → `NullReferenceException` (NRE) — в рантайме.

## Nullable<T> — «null» для значимых типов
`int?` = `Nullable<int>` — **структура** с полями `bool HasValue` и `T Value`. Живёт как struct (в стеке, если локальная).
- `HasValue` — есть ли значение.
- `Value` — значение; **бросает `InvalidOperationException`**, если `HasValue == false`.
- `GetValueOrDefault()` — значение или `default(T)`, без исключения (безопаснее).

## Операторы
- **`?.`** (null-conditional) — «если слева не null, обратись к члену; иначе верни null, не падая». Результат становится nullable: `name?.Length` имеет тип `int?`, а не `int`.
- **`??`** (null-coalescing) — «левое; если null — правое». `name ?? "аноним"`.
- **`??=`** — присвоить, **только если сейчас null**. `x ??= y;` ≡ `if (x == null) x = y;`. Если `x` уже не null — не делает ничего.

Комбинация: `int len = name?.Length ?? 0;`

## Разница ?. и прямого доступа
При `a == null`: `a.B` → **NRE (падение)**; `a?.B` → **безопасно возвращает null**.

## NRT (Nullable Reference Types)
Включается `<Nullable>enable</Nullable>` (в новых шаблонах по умолчанию). Компилятор различает `string` (не должен быть null) и `string?` (может). Даёт **предупреждения** (CS8602 и др.).
**Важно:** это только статический анализ на этапе компиляции. В рантайме null по-прежнему возможен — NRT не запрещает, а помогает не забыть. `!` (null-forgiving) гасит предупреждение, но не защищает.

## Практика
`int len = name?.Length ?? 0;` — типовой безопасный паттерн.
