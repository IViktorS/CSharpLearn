# 1.13 — Кортежи (tuples) и деконструкция

## Зачем
Метод умеет вернуть только **одно** значение. Когда нужно два-три, варианты были такие:
- `out`-параметры (тема 1.11) — работают, но громоздко и не везде разрешены;
- отдельный класс/структура (темы 1.1–1.2) — правильно, но заводить целый тип ради «вернуть min и max» тяжело.

Кортеж — третий вариант: сгруппировать несколько значений **без объявления типа**.

## Два разных «кортежа»
| | `System.Tuple<...>` (C# 4, legacy) | `System.ValueTuple<...>` (C# 7, синтаксис `( )`) |
|---|---|---|
| Категория | **class** → куча, передача по ссылке (1.1, 1.3) | **struct** → значимый тип, копируется при передаче |
| Члены | свойства `Item1..Item8`, только чтение | публичные **поля** `Item1..`, изменяемые |
| Имена элементов | нет | есть |
| Создание | `Tuple.Create(1, "a")` | `(1, "a")` |

Используем только `ValueTuple`. `Tuple<>` встретишь в старом коде — узнать и не пугаться.

```csharp
(int, string) t = (1, "Аня");           // без имён → t.Item1, t.Item2
(int Id, string Name) u = (1, "Аня");   // с именами → u.Id, u.Name (u.Item1 тоже работает)
var v = (Id: 1, Name: "Аня");           // имена заданы на стороне значения
```

## Как устроено: имена — сахар компилятора
В рантайме тип **один**: `ValueTuple<int, string>`. Полей с именами `Id`/`Name` физически не существует — компилятор при сборке переписывает `u.Id` в `u.Item1`.

Следствия (все три вытекают из одного факта — тип один и тот же):
- `(int Id, string Name)` и `(int Code, string Text)` — **один тип**, присваиваются друг другу свободно;
- `Console.WriteLine(u)` печатает `(1, Аня)` — имён там нет, печатать нечего;
- нельзя объявить две перегрузки метода, различающиеся только именами элементов, — для компилятора это два одинаковых метода.

Аналогия с уже пройденным: `const` (1.9) тоже исчезает при компиляции — значение инлайнится в место использования. Имена элементов кортежа так же живут только до компиляции.

## Метод, возвращающий кортеж
```csharp
static (int Min, int Max) MinMax(int[] data)
{
    int min = data[0], max = data[0];
    foreach (int x in data) { if (x < min) min = x; if (x > max) max = x; }
    return (min, max);      // имена подставляются ПО ПОЗИЦИИ
}

var r = MinMax(arr);
Console.WriteLine(r.Min);
```
Сравнение с `out` (1.11): кортеж короче и его можно вернуть выражением. `out` остаётся нужен там, где есть устоявшийся контракт — `TryParse`-паттерн (`bool` через `return`, значение через `out`).

## Деконструкция
Разложить кортеж на отдельные переменные:
```csharp
(int min, int max) = MinMax(arr);   // объявляем обе переменные
var (min, max)     = MinMax(arr);   // то же, типы выводятся
(min, max)         = MinMax(arr);   // присваиваем в уже существующие
(var min, int max) = MinMax(arr);   // можно смешивать
(min, _)           = MinMax(arr);   // _ (discard) — значение не нужно, переменная не создаётся
```
Два правила, из которых всё остальное следует:
1. **Число переменных должно точно совпадать** с числом элементов. «Взять только первые два из трёх» нельзя — для этого и есть `_`.
2. **Сопоставление по позиции.** Имена переменных с именами элементов кортежа не связаны никак: `var (y, x) = p;` положит в `y` первый элемент, как бы он ни назывался.

## Swap без временной переменной
```csharp
(a, b) = (b, a);
```
Механизм: **вся правая часть вычисляется до того, как начнутся присваивания**. Сначала создаётся кортеж из старых `b` и `a`, затем он раскладывается по переменным. Это общее правило вычисления выражений, а не идиома для swap — и оно объясняет, почему трюк работает без потери значения.

## Деконструкция своих типов: метод `Deconstruct`
Кортежи — не единственное, что деконструируется. Любой класс или структура получает такую возможность, если объявить метод `Deconstruct` с `out`-параметрами (тема 1.11):
```csharp
public class Point
{
    public int X { get; init; }      // тема 1.6
    public int Y { get; init; }

    public void Deconstruct(out int x, out int y)   // тема 1.11
    {
        x = X;
        y = Y;
    }
}

var (x, y) = point;    // компилятор вызывает point.Deconstruct(out x, out y)
```
Требования: имя ровно `Deconstruct`, возвращает `void`, все параметры — `out`. Перегрузок может быть несколько (с разным числом `out`) — тогда компилятор выберет по числу переменных слева.

Важно: сам объект тут **не** превращается в кортеж. `var (x, y) = point` — это вызов метода, а не создание `ValueTuple`.

## Равенство
`ValueTuple` сравнивается оператором `==` **поэлементно**:
```csharp
(1, "a") == (1, "a")                    // true
(Id: 1, Name: "a") == (Code: 1, Text: "a")   // true — имена не участвуют
```
Это отличается от того, что мы видели в 1.2: у обычной структуры `==` из коробки нет, а `class` сравнивается по ссылке. `ValueTuple` — особый случай, компилятор разворачивает `==` в сравнение элементов по очереди.

Ловушка в legacy: у `Tuple<>` (класс!) `==` сравнивает **ссылки** — два разных объекта с одинаковым содержимым дадут `false`.

## Грабли
1. **Это struct → копируется** (тема 1.1). `var b = a; b.Item1 = 99;` — `a` не изменится.
2. **Мутация «на месте» в коллекции** — ровно та же ловушка, что в 1.2: `list[i].Item1 = 5` даёт **CS1612** (индексатор возвращает копию), а `arr[i].Item1 = 5` законно (элемент массива — сама ячейка).
3. **Приведение к `object` теряет имена.** Внутри `object` лежит `ValueTuple<int, string>` — при обратном приведении доступны только `Item1`/`Item2`. Плюс это boxing (тема 1.4): структура уезжает в коробку на куче.
4. **Изменяемая структура с публичными полями.** Всё, что говорилось в 1.2 про опасность таких struct, применимо: кортеж — для передачи значения, а не для хранения долгоживущего состояния.
5. **Больше 3–4 элементов** — `Item5` не говорит ни о чём, читаемость падает. Это сигнал, что нужен настоящий тип.
6. **Нет валидации и поведения.** Кортеж не умеет проверить, что `Min <= Max`. Логика останется размазанной по вызывающему коду.

## Когда что
| Ситуация | Что |
|---|---|
| Вернуть 2–3 значения из внутреннего/`private` метода | **кортеж** |
| Локально сгруппировать пару значений | **кортеж** |
| Поменять переменные местами | `(a, b) = (b, a)` |
| Устоявшийся `TryXxx`-контракт | `out` (1.11) |
| Тип возвращается из публичного API, живёт дальше одного метода, имеет валидацию/поведение | `class` / `struct` (1.1–1.2) |

## Опирается на
- **1.1 / 1.3** — `ValueTuple` это struct: копирование при передаче, где живут данные.
- **1.2** — критерий «когда struct»; ловушка мутации элемента коллекции (CS1612).
- **1.4** — приведение кортежа к `object` = boxing.
- **1.6** — свойства (в примере `Deconstruct`).
- **1.9** — аналогия «исчезает при компиляции» (`const` инлайнится, имена элементов стираются).
- **1.11** — `out`-параметры: и как альтернатива кортежу, и как основа `Deconstruct`.
