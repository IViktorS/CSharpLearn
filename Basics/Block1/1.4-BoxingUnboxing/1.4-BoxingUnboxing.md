# 1.4 — Boxing / Unboxing

## Что это
- **Boxing** — упаковка значимого типа в объект-«коробку» на **куче**, чтобы обращаться к нему как к ссылочному (`object`/интерфейс).
- **Unboxing** — обратная распаковка из коробки в значимый тип.

## Механика
```csharp
int n = 42;
object o = n;      // BOXING: в куче создан объект, туда СКОПИРОВАНО 42, o хранит ссылку
int m = (int)o;    // UNBOXING: проверка типа + копирование значения обратно
```
- Коробка = обычный объект в куче (с заголовком ~16 байт) + скопированное значение.
- И упаковка, и распаковка — **копирование**. Коробка независима от оригинала: `n = 100` не меняет содержимое коробки (там остаётся 42).

## Unboxing требует ТОЧНОГО типа
Распаковать можно **только в тот же тип**, что лежит в коробке. `object o = 11.11;` (double) → `(int)o` бросает **`InvalidCastException`** сразу, без конвертации. Правильно: `(int)(double)o` (сначала unbox в double, потом каст → 11). Безопасно: `o is int` / `o is double d`.

## Зачем boxing существует
Не фича ради себя, а **плата за единую систему типов** (всё — `object`). Нужен, когда значимый тип попадает в контекст `object`/интерфейса. Массовый/случайный boxing — проблема производительности, которую убрали **дженериками**.

## Где ловить случайно
`ArrayList`/`Hashtable` (не-дженерик коллекции), `IComparable c = 5;`, старый `string.Format`, `params object[]`.

## Эксперимент
`ArrayList` на 5 млн `int` → **17 сборок Gen0**; `List<int>` → **0** (хранит `int` без упаковки).

## Память
`object test = 22;` — переменная в стеке (ссылка), коробка в куче (заголовок + значение). Как обычный `class`.
