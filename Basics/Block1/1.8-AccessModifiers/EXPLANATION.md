# 1.8 — Модификаторы доступа (все 6)

## Две оси доступа
1. **По наследованию** — видно ли производным классам (`protected`).
2. **По сборке (assembly)** — видно ли в пределах этого проекта/DLL (`internal`).
> Сборка = результат компиляции (`.dll`/`.exe`). У нас `Basics` и `CSharpLearn` — две сборки.

## Шесть модификаторов (от открытого к закрытому)
| Модификатор | Кто видит |
|---|---|
| `public` | все и везде |
| `internal` | только своя сборка |
| `protected` | сам класс + наследники (в любой сборке) |
| `protected internal` | наследники **ИЛИ** любой код своей сборки (объединение, шире) |
| `private protected` | наследники **И** только своя сборка (пересечение, уже — самый закрытый после private) |
| `private` | только сам класс |

## Хитрые комбинации
- **`protected internal`** = `protected` ИЛИ `internal` (доступ если наследник ИЛИ в той же сборке).
- **`private protected`** = `protected` И `internal` (доступ только если наследник И в той же сборке).
Мнемоника: слово `private` → строже.

## Значения по умолчанию
- **члены класса** (поля/методы/свойства) → **`private`**;
- **тип на верхнем уровне** → **`internal`** (не public!).

## Практика
Открывай наружу минимум. По умолчанию `private`, повышай по необходимости. Лазейка для `internal` из другой сборки — атрибут `[InternalsVisibleTo]`.

## Тонкость
Статичность класса-контейнера **не влияет** на видимость `protected`-члена базового класса. `protected` недоступен из чужого класса просто потому, что тот не наследник.
