## 1. Зачем / какую проблему решает

Модификатор доступа отвечает на один вопрос: **кому разрешено обращаться к члену по имени в коде**.

Смысл в том, чтобы сузить круг тех, кто может завязаться на деталь. Поле, которое видят только методы самого класса, можно переименовать, заменить или убрать — сломается только этот класс. Поле, открытое всем, может оказаться нужным кому угодно, и любое изменение превращается в поиск по всему решению.

Отсюда правило по умолчанию: **открывать минимум, повышать доступ только по необходимости.**

> [док] [Access modifiers (C# programming guide)](https://learn.microsoft.com/dotnet/csharp/programming-guide/classes-and-structs/access-modifiers)

## 2. Как устроено

### Это проверка компилятора, а не стена в памяти

Главное, что стоит знать о модификаторах: их проверяет **компилятор, когда собирает код**. В работающей программе объект один и тот же, его поля лежат в памяти одинаково, и никакой «двери с замком» перед `private`-полем нет.

**[проверено]** (механизм — тема 1.20): закрытое поле `Priv` класса `Base` записано через рефлексию **из другой сборки**:

```
private Priv из ЧУЖОЙ сборки через рефлексию: записано, читается 42
```

Вывод: модификатор защищает **от ошибок и от случайных зависимостей**, а не от того, кто решил обойти правила. Это контракт между частями кода, а не средство безопасности.

### Две оси

Модификаторы отвечают на два независимых вопроса:

1. **Своя ли сборка?** — ось `internal`.
2. **Наследник ли?** — ось `protected`.

`public` и `private` — крайние случаи: «всем» и «только самому классу». Две оставшиеся комбинации собираются из двух осей — это видно в таблице ниже.

### Полная таблица доступа

Все клетки проверены компилятором. Класс `Base` объявлен в библиотеке `LibA`; к его полям обращаются из пяти мест — сам класс, наследник и обычный класс в той же сборке, наследник и обычный класс в другой сборке:

```csharp
// сборка LibA
public class Base
{
    public int Pub;
    internal int Int;
    protected int Prot;
    protected internal int ProtInt;
    private protected int PrivProt;
    private int Priv;
}

class SameDerived : Base { /* обращается к полям как к своим: Pub = 1; Int = 1; ... */ }
class SameOther          { /* обращается через объект:        b.Pub = 1; b.Int = 1; ... */ }

// сборка Other — ссылается на LibA
class OtherDerived : Base { /* так же */ }
class OtherOther          { /* так же */ }
```

**[проверено]**, ✓ — компилируется, ✗ — ошибка:

| Модификатор | сам класс | своя сборка, наследник | своя сборка, другой класс | чужая сборка, наследник | чужая сборка, другой класс |
|---|---|---|---|---|---|
| `public` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `internal` | ✓ | ✓ | ✓ | ✗ | ✗ |
| `protected` | ✓ | ✓ | ✗ | ✓ | ✗ |
| `protected internal` | ✓ | ✓ | ✓ | ✓ | ✗ |
| `private protected` | ✓ | ✓ | ✗ | ✗ | ✗ |
| `private` | ✓ | ✗ | ✗ | ✗ | ✗ |

Строки комбинаций **выводятся** из строк `internal` и `protected`, сравни столбцы:

- **`protected internal` = `protected` ИЛИ `internal`** — ✓ там, где ✓ хотя бы в одной из двух строк. Шире каждой.
- **`private protected` = `protected` И `internal`** — ✓ только там, где ✓ в обеих. Уже каждой; самый закрытый после `private`.

Мнемоника: слово `private` в названии делает строже.

### Из чужой сборки закрытое выглядит как отсутствующее

Ошибки в таблице — разные, и это полезно знать. **[проверено]**:

```
своя сборка,  private:                       error CS0122: "Base.Priv" недоступен из-за его уровня защиты.
чужая сборка, protected у не-наследника:     error CS0122: "Base.Prot" недоступен из-за его уровня защиты.
чужая сборка, private или internal:          error CS0103: Имя "Priv" не существует в текущем контексте.
                                             error CS1061: "Base" не содержит определения "Int" ...
```

Для члена, который из чужой сборки не может быть доступен **ни при каких условиях** (`private`, `internal`), компилятор пишет не «недоступен», а «**не существует**». В исходнике член есть, а ошибка утверждает, что его нет. Если видишь такое — первым делом проверь модификатор.

### Дружественная сборка: `[InternalsVisibleTo]`

Атрибут `[assembly: InternalsVisibleTo("Friend")]` в сборке `LibA` объявляет сборку `Friend` «своей» по оси `internal`. **[проверено]**, та же проверка из сборки `Friend`:

| Модификатор | наследник в `Friend` | другой класс в `Friend` |
|---|---|---|
| `public` | ✓ | ✓ |
| `internal` | ✓ | ✓ |
| `protected` | ✓ | ✗ |
| `protected internal` | ✓ | ✓ |
| `private protected` | ✓ | ✗ (CS0281, см. граблю 4) |
| `private` | ✗ | ✗ |

Ровно таблица «своей сборки»: дружба открывает ось сборки и не трогает ось наследования.

### Значения по умолчанию

**[проверено]** рефлексией на `LibA`:

```
тип верхнего уровня без модификатора: IsPublic=False, IsNotPublic=True  (internal)
вложенный тип без модификатора:      IsNestedPrivate=True
член без модификатора:                IsPrivate=True
```

| Что объявлено без модификатора | Получает |
|---|---|
| класс на верхнем уровне | **`internal`** — не `public`! |
| класс, вложенный в другой | `private` |
| поле, метод, свойство | `private` |

## 3. Синтаксис

Модификатор пишется первым в объявлении. Составные — два слова через пробел, порядок любой (`protected internal` = `internal protected`) — **[проверено]**: у обоих полей рефлексия даёт один и тот же уровень `IsFamilyOrAssembly`. Пример ниже собирается без ошибок:

```csharp
public class Service
{
    private readonly int _cache;           // деталь реализации
    internal void ResetForTests() { }      // видно внутри проекта
    protected virtual void OnChanged() { } // точка расширения для наследников (Блок 2)
    public int Count { get; private set; } // читают все, пишет только сам класс (1.6)
}
```

Последняя строка — модификатор на отдельном методе доступа свойства: свойство открыто, а запись закрыта. Это тот самый `private set` из 1.6 — и из задачи 1 темы 1.20, где выяснилось, что рефлексия его тоже обходит.

## 4. Грабли

**1. «`private` — значит, защищено».** Нет: проверку делает компилятор, рефлексия её обходит (раздел 2). От ошибок защищает, от умысла — нет.

**2. Забытый `public` у класса.** Класс без модификатора — `internal`. Внутри своего проекта всё работает, из другого проекта класс «не существует». Ошибка всплывает только при первом обращении из другой сборки.

**3. Путать `protected internal` и `private protected`.** Первый — **ИЛИ**, шире каждой оси. Второй — **И**, уже каждой. Звучат похоже, означают почти противоположное.

**4. Сообщение CS0281 вводит в заблуждение.** При `[InternalsVisibleTo]` попытка обратиться к `private protected` из **не-наследника** даёт **[проверено]**:

```
error CS0281: Дружественный доступ предоставлен "LibA, ...", однако открытый ключ выходной сборки ("")
              не соответствует ключу, определенному атрибутом InternalsVisibleTo предоставляющей сборки.
```

Сообщение про ключи, но ключи ни при чём: **наследник в той же сборке `Friend` к тому же полю доступ получил** (таблица выше). Настоящая причина — у `private protected` не выполнена ось наследования.

**5. Статичность класса не влияет на `protected`.** `protected`-член базового класса недоступен из чужого класса просто потому, что тот не наследник, — статический он или нет, роли не играет. *(Пункт из исходного конспекта, утверждение Claude; отдельно не перепроверялся.)*

## 5. Когда что

| Нужно | Модификатор |
|---|---|
| деталь реализации класса | `private` — по умолчанию для всего |
| деталь реализации проекта, видная его классам | `internal` |
| то, чем пользуются снаружи проекта | `public` |
| точка расширения для наследников | `protected` (Блок 2) |
| наследникам — только внутри своего проекта | `private protected` — редкость |
| наследникам везде плюс всему своему проекту | `protected internal` — редкость |
| открыть `internal` одному конкретному проекту (обычно тестам) | `[InternalsVisibleTo]` |

## 5б. Где встретится в реальном коде

- **CS0103 / CS1061 «не существует» на члене, который в исходнике есть** — почти всегда член `internal` или `private` в другой сборке. Сообщение уводит в сторону: кажется, что не та версия библиотеки.
- **`[assembly: InternalsVisibleTo("Проект.Tests")]`** — в `AssemblyInfo.cs` или в `.csproj` как `<InternalsVisibleTo Include="..." />`. Почти всегда это тестовый проект, которому открыли внутренности (Блок 9).
- **`BindingFlags.NonPublic` в тестах и сериализаторах** — обход `private` через рефлексию (1.20). Работает, но ломается при переименовании.
- **Публичное поле на ревью** — стандартное замечание «сделай свойство» (1.6): поле нельзя потом снабдить проверкой, не меняя то, как к нему обращаются.
- **`public set` там, где нужен `private set`** — свойство, которое снаружи только читают, но кто угодно может перезаписать.
