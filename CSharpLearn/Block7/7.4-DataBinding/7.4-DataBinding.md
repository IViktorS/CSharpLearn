# 7.4 Data Binding — режимы и триггеры

Задачи — `DataBinding.xaml` (+ `.xaml.cs` с кнопками). Запуск:

```bash
dotnet run --project CSharpLearn -- 7.4
```

Пометки происхождения: **[проверено]** — собрано и запущено в харнессе (консольный проект с `UseWPF`, элементы создаются в коде, значения читаются напрямую), вывод приложен; **[док]** — ссылка на документацию; без пометки — утверждение Claude.

> Мини-справка: **dependency property** — особое свойство WPF (тема 8.1). Из 7.3 известно, что его значение может приходить от родителя. Здесь важно другое его умение: **оно сообщает, когда меняется**. Почти все свойства элементов (`Text`, `Value`, `Width`, `IsChecked`) — такие.

> Мини-справка: **потеря фокуса** — момент, когда поле ввода перестаёт быть активным: нажали Tab, щёлкнули мышью в другое место. WPF сообщает об этом событием `LostFocus` (события — Блок 3; здесь это чёрный ящик «момент, когда фокус ушёл»).

## 1. Зачем / какую проблему решает

Без биндинга экран и данные синхронизируют руками: в одну сторону — `textBox.Text = person.Name`, в другую — `person.Name = textBox.Text`, и обе строки надо не забыть вызвать в правильные моменты.

Биндинг — **декларация связи**: «это свойство элемента связано с тем свойством источника». Дальше WPF сам переносит значение — в нужную сторону и в нужный момент.

7.3 ответила на вопрос «откуда источник по умолчанию» — из `DataContext`. Эта тема — про три других вопроса:

1. **В какую сторону** идут значения — режим (`Mode`).
2. **Когда** значение уходит в источник — триггер (`UpdateSourceTrigger`).
3. **Как указать другой источник**, если `DataContext` не подходит — `ElementName`, `RelativeSource`.

> [док] [Data binding overview (WPF)](https://learn.microsoft.com/dotnet/desktop/wpf/data/)

## 2. Как устроено

### Две стороны: цель и источник

```xml
<TextBox Text="{Binding Name}" />
```

- **Цель** — свойство элемента, в котором стоит биндинг: `TextBox.Text`. Цель обязана быть dependency property.
- **Источник** — свойство объекта, на которое биндинг указывает: `Name` у `DataContext`. Источником может быть обычное свойство обычного класса.

Направления называются относительно этих двух сторон: «источник → цель» — значение пришло на экран; «цель → источник» — то, что ввёл пользователь, ушло в объект.

### Режим и триггер по умолчанию задаёт свойство ЦЕЛИ

Самое неочевидное в теме. Если в биндинге не написано `Mode=...`, режим берётся **не из биндинга, а из описания свойства цели**. То же с моментом записи в источник.

**[проверено]**, метаданные свойств:

| Свойство цели | Двусторонний по умолчанию | Когда пишет в источник |
|---|---|---|
| `TextBox.Text` | да | **при потере фокуса** (`LostFocus`) |
| `TextBlock.Text` | нет — только источник → цель | — |
| `Slider.Value` | да | сразу (`PropertyChanged`) |
| `CheckBox.IsChecked` | да | сразу (`PropertyChanged`) |

Отсюда два разных поведения при одинаковой записи `{Binding X}`: `TextBlock` только показывает, а `TextBox` и показывает, и пишет обратно. Причём пишет **не на каждую букву**, а когда пользователь ушёл из поля. Логика понятна: значение «32» на полпути от «3» к «325» в источник лучше не отправлять — но это утверждение о мотиве, и экспериментом его не проверить.

### Четыре режима

**[проверено]**, источник — `Slider.Value` (стартует с 10), цель — `TextBox.Text`, триггер выставлен в `PropertyChanged`, чтобы не ждать фокуса:

| Режим | Старт | Ползунок → 20 | В поле набрали «30» |
|---|---|---|---|
| `OneWay` | `Text = "10"` | `Text = "20"` | ползунок **остался** на 20 |
| `TwoWay` | `Text = "10"` | `Text = "20"` | ползунок **ушёл** на 30 |
| `OneTime` | `Text = "10"` | `Text` **остался** `"10"` | ползунок остался на 20 |
| `OneWayToSource` | `Text` **пустой** | `Text` остался пустым | ползунок ушёл на 30 |

- `OneWay` — только на экран.
- `TwoWay` — в обе стороны.
- `OneTime` — один раз при подключении, дальше связь не следит за источником.
- `OneWayToSource` — только с экрана в источник; на старте поле даже **не заполняется** из источника.

### Триггер: когда значение уходит в источник

**[проверено]**, `TextBox.Text` ↔ `Name` обычного объекта (было «Анна»), в поле набрали «Борис»:

| `UpdateSourceTrigger` | Сразу после набора | После потери фокуса | После `UpdateSource()` в коде |
|---|---|---|---|
| не указан (у `TextBox` это `LostFocus`) | Анна | **Борис** | Борис |
| `PropertyChanged` | **Борис** | Борис | Борис |
| `Explicit` | Анна | Анна | **Борис** |

`Explicit` — значение уходит, только когда код сам скажет: `textBox.GetBindingExpression(TextBox.TextProperty).UpdateSource()`. Применяется для форм с кнопкой «Сохранить».

### Другие источники вместо `DataContext`

| Запись | Источник |
|---|---|
| `{Binding Name}` | `DataContext` (7.3) |
| `{Binding Value, ElementName=Volume}` | элемент с `x:Name="Volume"` |
| `{Binding ActualWidth, RelativeSource={RelativeSource Self}}` | сам элемент, в котором стоит биндинг |
| `{Binding Title, RelativeSource={RelativeSource AncestorType=Window}}` | ближайший предок указанного типа вверх по дереву |
| `{Binding Source={StaticResource AppName}}` | ресурс (7.2) |

**[проверено]**: `TextBlock` с `Tag = "мой собственный Tag"` и `Text="{Binding Tag, RelativeSource={RelativeSource Self}}"` показывает `мой собственный Tag`. Отдельно **[проверено]** в показанном окне: `ElementName` и `RelativeSource AncestorType=Window` находят свой источник и следят за его изменениями; ресурсный вариант (`Source={StaticResource ...}`) не прогонялся.

### Источник поменялся сам — что видно на экране

Здесь три случая, и они ведут себя по-разному.

**1. Источник — свойство другого элемента.** Всё работает в обе стороны: свойства элементов — dependency properties, и они сообщают о своих изменениях. Это видно в таблице режимов: ползунок двигается — поле обновляется.

**2. Источник — обычный класс, значение изменил ДРУГОЙ биндинг.** Обновляются **все** поля, связанные с этим свойством. **[проверено]**: три элемента связаны с одним `Name`, во второе поле (`PropertyChanged`) набрали «Глеб»:

```
старт:                          first=[Анна] second=[Анна] shown=[Анна] p.Name=Анна
во второе поле набрали «Глеб»: first=[Глеб] second=[Глеб] shown=[Глеб] p.Name=Глеб
```

Объяснение — утверждение Claude, из замера оно не видно: биндинг записывает значение в источник через собственный механизм WPF и при этом сам рассылает уведомление остальным биндингам на то же свойство.

**3. Источник — обычный класс, значение изменили В КОДЕ.** На экран не попадает ничего. **[проверено]**, продолжение того же опыта:

```
в коде p.Name = "Вера":         first=[Глеб] second=[Глеб] shown=[Глеб] p.Name=Вера
```

Объект уже «Вера», на экране «Глеб». Это та же история, что в грабле 4 темы 7.3: обычный класс сам об изменениях не сообщает, а присваивание в коде идёт мимо механизма WPF. Как научить класс сообщать — тема 7.6.

Итог: **с экрана в объект — работает всегда; между полями через общий объект — работает; из кода на экран — только для объектов, которые умеют сообщать.**

## 3. Синтаксис

```xml
<!-- источник — DataContext, режим и триггер по умолчанию -->
<TextBox Text="{Binding Name}" />

<!-- явный режим и триггер -->
<TextBox Text="{Binding Name, Mode=TwoWay, UpdateSourceTrigger=PropertyChanged}" />

<!-- источник — другой элемент -->
<Slider x:Name="Volume" Minimum="0" Maximum="100" />
<TextBlock Text="{Binding Value, ElementName=Volume}" />

<!-- источник — сам элемент -->
<TextBlock Text="{Binding ActualWidth, RelativeSource={RelativeSource Self}}" />

<!-- источник — ближайший Window вверх по дереву -->
<TextBlock Text="{Binding Title, RelativeSource={RelativeSource AncestorType=Window}}" />
```

## 4. Грабли

**1. `TextBox` пишет в источник не сразу.** По умолчанию — при потере фокуса (таблица выше). Симптом: пользователь ввёл значение и сразу нажал кнопку на панели инструментов, которая фокус не забирает, — а в объекте всё ещё старое значение. Лечится `UpdateSourceTrigger=PropertyChanged` там, где это нужно.

**2. Не преобразовалось — тихо.** **[проверено]**: в поле, связанное с `int Age`, набрали `abc`:

```
Text="abc" → Age=30, Validation.HasError=True
Text="45"  → Age=45, Validation.HasError=False
```

Исключения нет. Значение в источник просто не ушло, а поле получило признак ошибки — на экране это красная рамка вокруг поля. Пока ошибка висит, объект хранит последнее корректное значение.

**3. Двусторонний биндинг на свойство только для чтения — исключение, и не там, где ждёшь.** `TextBox.Text` по умолчанию двусторонний, а свойство `public string Code => ...` записи не имеет. **[проверено]**:

```
разметка загружена без ошибок
при выставлении DataContext: InvalidOperationException
  "Привязка типа TwoWay или OneWayToSource не может работать с доступным
   только для чтения свойством "Code" типа "Person"."
```

Компиляция и загрузка разметки проходят. Падение случается, когда у биндинга появляется источник. Лечится `Mode=OneWay` — или `TextBlock` вместо `TextBox`, если поле всё равно только для показа.

**4. `OneWayToSource` не показывает начальное значение.** Поле стартует пустым, даже если в источнике что-то есть (таблица режимов).

**5. `OneTime` молча перестаёт обновляться.** Внешне ничем не отличается от `OneWay` — до первого изменения источника.

**6. Изменение обычного объекта в коде не видно — а изменение через другой биндинг видно.** Два поля на одном свойстве синхронизируются между собой, а присваивание в коде не попадает ни в одно (раздел 2). Легко сделать неверный вывод из первого случая и удивиться второму.

## 5. Когда что

| Нужно | Как |
|---|---|
| только показать | `TextBlock`, режим по умолчанию |
| поле ввода, значение нужно в объекте после ухода из поля | `TextBox`, по умолчанию |
| поле ввода, значение нужно в объекте на каждую букву (поиск, фильтр) | `UpdateSourceTrigger=PropertyChanged` |
| форма с кнопкой «Сохранить», а до неё объект трогать нельзя | `UpdateSourceTrigger=Explicit` + `UpdateSource()` |
| показать значение один раз и не следить | `Mode=OneTime` |
| `TextBox` на свойство только для чтения | `Mode=OneWay` (иначе исключение) |
| связать два элемента между собой | `ElementName` |
| свойство самого элемента или его предка | `RelativeSource Self` / `AncestorType` |

## 5б. Где встретится в реальном коде

- **«Ввёл значение, нажал “Сохранить” — сохранилось старое».** Кнопка на панели инструментов или пункт меню фокус из поля не забирают, а `TextBox` пишет в источник только при потере фокуса. Чаще всего встречается именно в таком виде; лечится `PropertyChanged` на полях, которые читаются сразу.
- **Красная рамка вокруг поля, а в объекте старое число** — грабля 2. Обычно это ввод не того формата в числовое поле.
- **`InvalidOperationException` про «TwoWay … только для чтения» при открытии окна** — грабля 3. В стеке будет установка `DataContext`, а не сама разметка.
- **`Mode=TwoWay` у `TextBox`** — встречается часто, но для `Text` это и так значение по умолчанию; написанное явно ничего не меняет. На ревью иногда просят убрать как шум, иногда оставить как документацию — вопрос стиля команды.
- **`{Binding DataContext.Command, RelativeSource={RelativeSource AncestorType=Window}}`** внутри шаблонов списков — способ дотянуться до `DataContext` окна, когда у текущего элемента свой. Узнаётся по длинной цепочке в пути.
