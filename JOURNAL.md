- Тема 1.4 закрыта: boxing = упаковка значимого типа в объект-коробку на куче (копия значения + заголовок ~16б), unboxing требует ТОЧНОГО совпадения типа (иначе InvalidCastException, не конвертация). boxing — не фича, а плата за единую систему типов; убирается дженериками. Эксперимент: ArrayList на 5 млн int → 17 сборок Gen0, List<int> → 0. Понимает случайный boxing (object/интерфейс/ArrayList).
- Тема 1.5 закрыта: `Nullable<T>` (HasValue/Value/GetValueOrDefault; Value бросает InvalidOperationException при HasValue==false), `?.` (safe navigation, возвращает null а не падает; результат становится `int?`), `??`, `??=` (присваивает ТОЛЬКО если null — ошибка была тут: думал что всегда). Видел NRT-предупреждение CS8602 вживую. Разобрались с отладчиком VS (first-chance exception break — почему казалось, что catch не срабатывает).
- Тема 1.6 закрыта: свойство = метод-доступ (валидация в сеттере), `value` — параметр сеттера (только про запись), авто-свойство имеет скрытое backing-поле, `init` vs `set` (init только при создании; CS8852), `get`-only задаётся в конструкторе но НЕ через объектный инициализатор, вычисляемое свойство не хранит значение, `private set` = менять только внутри класса (CS0272).
- Тема 1.7 закрыта (без ошибок): enum = именованные целые (нумерация с 0), каст в int, `(Status)99` хранится и печатается числом (неполная типобезопасность → `Enum.IsDefined`), default=0. `[Flags]`: степени двойки, `|` добавить, `&`+`~` снять, `HasFlag`, красивый ToString. `Enum.TryParse` при неудаче → out = default(0); проверять возвращаемый bool.
- Тема 1.8 закрыта: 6 модификаторов по двум осям (наследование/`protected` + сборка/`internal`). `protected internal` = ИЛИ (шире), `private protected` = И (уже, более закрытый). Дефолты: тип на верхнем уровне = internal, член = private. Мелкая поправка: static класса не влияет на видимость protected-члена. Знает про [InternalsVisibleTo] как лазейку.
- Тема 1.9 закрыта (без ошибок): const = compile-time, неявно static, инлайнится (→ проблема версионирования между сборками), только примитивы/string/enum. readonly = runtime (объявление/конструктор), per-instance, любой тип. readonly ссылочного типа защищает ССЫЛКУ, не содержимое (Items.Add ок, Items = new — нет, CS0191 при попытке переприсвоить readonly вне конструктора).
- Тема 1.10 закрыта (без ошибок): static = принадлежит типу, одно на весь тип, живёт до конца приложения; хранилище статики типа (loader heap), static-ссылка = GC-корень (→ утечки). static-метод без this → только к статике. static-класс: только static-члены, нельзя new/наследовать. static-конструктор: один раз, лениво (перед первым обращением к типу), вручную не вызвать. Опасность изменяемой static → static readonly.

- Тема 7.1 закрыта (2026-09-08), первая на WPF-треке. Компоновка = два прохода: Measure («сколько хочешь при таком доступном месте?») и Arrange («вот прямоугольник»); разница между панелями — в том, что каждая отвечает на этих проходах. `StackPanel` в направлении укладки выдаёт БЕСКОНЕЧНОСТЬ на Measure **независимо от своей собственной `Height`** — отсюда классика с `ScrollViewer`. Замерено: A) StackPanel > ScrollViewer → ScrollableHeight 0; B) `Height=200` на StackPanel → всё равно 0 (провокация, пользователь предсказал верно); C) `Height=200` на самом ScrollViewer → Viewport 200, Extent 2000, Scrollable 1800; D) строка Grid `*` → 1600. Правило: конечную высоту должен получить САМ `ScrollViewer`, содержимое остаётся неограниченным. `Grid`: `Auto` / число / `*` (доля остатка, не проценты) — при ширине 500 и Auto=120 звёздочка получает 380. `DockPanel`: порядок детей значим, `LastChildFill=true` по умолчанию. `Canvas` не измеряет и не обрезает. - Тема 1.15 закрыта (2026-09-14). У рекурсии нет своего механизма — это 1.3 в действии: кадр на вызов, кадр живёт до возврата, стек фиксирован. Проверено запуском: экземплярный метод побеждает молча (ни ошибки, ни предупреждения — это и есть грабля); на `null` падает не вызов, а тело, если оно разыменовывает параметр (кадр стека внутри расширения против кадра на строке вызова у экземплярного члена); выбор перегрузки идёт по ОБЪЯВЛЕННОМУ типу переменной — одна и та же строка дала `string-ext` и `object-ext`. Явный статический вызов поиск не запускает вовсе.

- **Методологический эпизод 1.16, важнее самой темы.** Первый замер упаковки дал 0,24 байта на вызов — то есть «упаковки нет» — и опроверг бы верный ответ пользователя. Причина: коробка не покидала метод, и JIT её устранил. Второй замер (коробка сохраняется в статическое поле) дал 24 байта на вызов и 2 сборки Gen0 против 0 у строки. Формулировка: на уровне ЯЗЫКА упаковка происходит всегда (это семантика, компилятор обязан её вставить), а будет ли реальное выделение памяти — решает JIT. Первый эксперимент не отличал «упаковки нет» от «упаковка устранена оптимизацией»; второй отличает. Это буквальная иллюстрация правила из раздела «Доверие к конспекту».
